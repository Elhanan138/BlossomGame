# Blossom · משחק ציורים וניחושים

משחק חברה קבוצתי בעברית לימי גיבוש. כל משתתף מצייר בטלפון ביטוי סודי, השאר ממציאים מה צויר, וכולם מצביעים איזו תשובה אמיתית. מסך מרכזי מציג את המשחק לכל החדר.

- 3–12 משתתפים (מותאם במיוחד ל-9), בלי הרשמה ובלי אפליקציה, הצטרפות ב-QR או בקוד חדר.
- סנכרון בזמן אמת: Vercel Functions + Neon Postgres, לקוחות מתעדכנים כל שנייה. השרת הוא מקור האמת: טיימרים, ניקוד וסודות נשמרים רק בשרת.
- ממשק עברי מלא, RTL, Mobile-First למשתתפים ומסך הקרנה כהה למקרן.

## הפעלה ביום האירוע

1. פותחים את האתר במחשב ולוחצים **"פתיחת משחק חדש"**.
2. בוחרים הגדרות (סבבים, טיימרים, מצב רגיל/גיבוש). מוצג אומדן משך.
3. לוחצים **"פתיחת מסך הקרנה"** וגוררים את החלון למקרן (F11 למסך מלא).
4. המשתתפים סורקים את ה-QR, כותבים שם ונכנסים.
5. כשכולם בפנים, לוחצים **"מתחילים!"**. המשחק מתקדם לבד.
6. בעת הצורך: השהיה, +15 שניות, לשלב הבא, דילוג על ציור, סיום משחק.
7. בסוף: **"משחק חדש עם אותה חבורה"**.

אם משתתף מרענן או מתנתק, הוא חוזר אוטומטית לאותו מקום, עם השם, הניקוד והציור שנשמר.

## הרצה מקומית

דרישות: Node.js 20 ומעלה.

```bash
npm install
```

```bash
npm run dev
```

הממשק בכתובת http://localhost:5173 והשרת על פורט 3000. כדי לחבר טלפונים באותה רשת, פותחים מהטלפון את `http://<IP של המחשב>:5173`.

## Build והרצה בייצור

```bash
npm run build
```

```bash
npm start
```

השרת מגיש גם את הממשק וגם את ה-WebSocket מאותה כתובת (ברירת מחדל: פורט 3000).

## בדיקות

```bash
npm test
```

בדיקות יחידה ללוגיקת המשחק והניקוד, ובדיקת אינטגרציה שמריצה משחק מלא עם 9 לקוחות Socket.IO אמיתיים (כולל ניתוק וחזרה, הצבעה כפולה, תשובה באיחור ורענון מנחה).

```bash
npm run build && npm run e2e
```

בדיקת E2E ב-Playwright: מנחה, מסך הקרנה ו-3 טלפונים ברוחבים 320/375/430 משחקים משחק שלם דרך הממשק. בודקת שאין שגיאות בקונסול ושאין גלילה אופקית, ושומרת צילומי מסך ב-`test-results/`.

## פריסה (Vercel + Neon)

- **אתר חי:** https://blossom-kishkushon.vercel.app
- **Vercel:** הפרויקט `blossom-game` מחובר לריפו, וכל push ל-`main` נפרס אוטומטית. הפונקציות נמצאות ב-`api/` ורצות באזור fra1, והממשק נבנה עם `vite build`.
- **Neon:** הפרויקט `blossom-game` (eu-central-1). הטבלאות `rooms` ו-`images`, והסכמה ב-`src/server/store.ts`. ליצירה מחדש: `DATABASE_URL=... npm run db:migrate`.
- **Health check:** `GET /api/healthz` מבצע שאילתה אמיתית מול מסד הנתונים.

אפשר להריץ גם כשרת Node רגיל (Docker / `npm start`): עם `DATABASE_URL` הוא עובד מול Neon, ובלעדיו המצב נשמר בזיכרון.

### משתני סביבה

| משתנה | תיאור |
|---|---|
| `DATABASE_URL` | מחרוזת חיבור ל-Neon (מוגדרת ב-Vercel כ-Sensitive) |
| `MAX_ROOMS` | מקסימום חדרים פעילים (ברירת מחדל 300) |
| `ROOM_TTL_MINUTES` | חדר לא פעיל נמחק אחרי זמן זה (ברירת מחדל 240) |

## ארכיטקטורה

```
src/shared/types.ts   טיפוסים משותפים: שלבים, הגדרות, Views ואירועים
src/server/game.ts    מכונת המצבים של המשחק (Room): שלבים, טיימרים, ניקוד, הרשאות
src/server/api.ts     שכבת ה-API (טעינה/שמירה עם גרסאות, טיימרים, נוכחות)
src/server/store.ts   אחסון: Neon Postgres או זיכרון
api/                  Vercel Functions: rpc, img, healthz
src/server/prompts.ts ~160 ביטויים מקוריים + שאלות שיחה למצב גיבוש
src/client/           React + Vite: Landing, Player, Host, ScreenView, DrawCanvas
```

שלבים: `LOBBY → DRAWING → (ANSWERING → VOTING → REVEAL) × ציורים → ROUND_RESULTS → [DISCUSSION] → סבב הבא / FINAL`. כל המעברים בשרת.

כל לקוח מקבל View לפי התפקיד: המסך הציבורי לא מקבל אף פעם ביטוי או מחבר תשובה לפני החשיפה, ומשתתף רואה רק את הביטוי שלו.

**ניקוד (ניתן להגדרה בשרת):** ניחוש נכון 1,000. כל מי שנפל בתשובה שלך: 500 (אם כמה כתבו אותה תשובה, כל אחד מהם מקבל). בעל הציור מקבל 250 אם לפחות חצי מהמצביעים טעו.

**מקרי קצה:**
- תשובות זהות (אחרי נרמול רווחים, פיסוק וניקוד) מתאחדות לאפשרות אחת.
- תשובה זהה לביטוי המקורי נדחית עם בקשה לכתוב משהו אחר.
- אם הגיעו פחות משתי תשובות, נוספות "תשובות בית" כך שתמיד יש בחירה.
- מי שלא צייר מקבל ציור ריק עם הודעה משעשעת, והמשחק ממשיך.
- משתתפים מנותקים לא עוצרים את התקדמות השלב.

**אבטחה:**
- קודי חדר אקראיים (crypto).
- טוקן סודי לכל משתתף ולמנחה, מאומת בשרת בכל חזרה.
- הצטרפות רק בלובי.
- ולידציה ומגבלות אורך לשמות, תשובות וגודל ציור.
- Rate limiting לאירועים ולפתיחת חדרים.
- React מונע הזרקת HTML.
- מגבלת חדרים ומחיקה אוטומטית של נתונים.

## מגבלות ידועות

- הסנכרון מבוסס בקשות כל שנייה, כך שעדכון יכול להגיע באיחור של עד שנייה.
- הצטרפות באמצע משחק אינה אפשרית (רק בלובי). משתתף קיים יכול לחזור.
- ציור חופשי על קנבס אינו נגיש לחלוטין לקוראי מסך. שאר הממשק תומך במקלדת ובקורא מסך.
- נבדק ב-Chromium (כולל אמולציית טלפון). מומלץ לבדוק גם על iPhone ו-Android אמיתיים לפני האירוע.
